# 泄漏风险初筛算法与适用边界

## 1. 这个软件实际判断什么

输入是一段历史 TDMS 中指定的逻辑通道与采样窗口。输出不是“已经确认泄漏”，而是“哪些通道在该窗口内同时表现出幅值、局部空间差异和频谱形态异常，值得继续复核”。

原因是泄漏识别还依赖设备空间标定、运行工况、带标签历史事件和现场验证；这些信息不能从单段未标注历史 TDMS 中凭空推断。

## 2. 单窗口处理流程

```text
TDMS 有界读取
  -> RMS / peak / dominant frequency
  -> local RMS ratio
  -> 2–120 Hz log spectrum
  -> neighbour magnitude-squared coherence
  -> iterative background learning (median + MAD + guard channels)
  -> RMS Z + local ratio + spectral Z conjoint decision
  -> contiguous candidate-channel regions
```

### 关键特征

- **RMS**：衡量窗口内整体振动能量；使用 median/MAD 转成 robust Z，避免单个极大值主导均值与标准差。
- **局部 RMS 比**：每个通道同附近通道的中位 RMS 比较，筛掉全体同时抬升这类共模变化。
- **频谱偏离**：先计算 2–120 Hz 对数功率谱，再计算它与背景谱的稳健距离；目标是区分“能量变大”与“频谱结构也改变”。
- **相邻通道相干性**：用 SciPy 的 magnitude-squared coherence 计算相邻通道在同一频带内的一致性，作为输出证据，不单独决定报警。
- **迭代背景**：先选较安静通道，初步候选以及其附近保护通道不再参与背景重建，重复三轮；这样能降低疑似异常污染背景的风险。

单窗口候选条件是：`RMS Z >= 阈值`、`局部 RMS 比 >= 阈值`、`频谱 Z >= 阈值` **同时成立**。默认值分别是 2.5、1.10、2.0，可通过 API 参数调整。

## 3. 为什么还要“持续性”

一次瞬时异常可能来自偶发噪声、敲击、干扰或窗口边界。因此软件提供两种二次筛查：

- **多窗口持续性**：同一文件内，按设定步长取多个窗口；同一逻辑通道必须连续多次成为候选。
- **跨文件持续性**：从选中文件开始，在同目录按文件名顺序取连续 TDMS 文件；同一通道必须在连续文件中重复成为候选。

两种筛查还记录差分 RMS、主频均值/标准差和相邻相干性。主频波动过大时，即使满足重复次数也降为黄色风险，避免把不稳定的偶发扰动直接升级。

## 4. 分级与空间表达

单窗口候选默认是黄色；当 RMS 与频谱偏离远高于阈值时升为橙色或红色。连续逻辑通道会合并为一个候选区间，例如 `5–6 通道`。当前真实 TDMS 没有可信的距离标定元数据，因此界面只展示**通道号**，不虚构公里位置。

## 5. 当前边界与接入真实生产的必要工作

当前版本适合历史数据回放、算法原型和软件测试演示。接入真实生产场景前至少还要补：

1. 根据采集设备元数据标定“通道号 → 实际距离”；
2. 以真实采集时间戳而不是文件名排序；
3. 用已标注的泄漏/非泄漏数据做阈值标定，计算检出率、误报率与延迟；
4. 加入设备状态、工况、权限、审计、告警通知与部署监控；
5. 由现场流程复核候选区域，不能直接把算法结果视为泄漏事实。

因此，面试中的准确说法是：**“我完成的是可复现的 DAS 历史数据泄漏风险初筛与持续性预警原型，并为后续标定与现场联调保留了接口。”**
