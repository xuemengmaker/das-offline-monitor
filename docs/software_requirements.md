# DAS 离线回放软件需求与验收标准

## 1. 范围

本系统在 Ubuntu/WSL 中运行，从配置的数据根目录只读回放历史 TDMS 文件，生成管道泄漏**风险初筛**和持续性预警证据。它不控制采集硬件、不改写原始数据，也不替代现场确认。

## 2. 功能需求

### 数据安全与任务

- 只接受数据根目录内、不含 `..` 的 `.tdms` 相对路径；
- 在任务创建前校验文件，在后台校验通道范围与采样窗口；
- 有界读取指定的通道和采样点，单任务最多 50,000 点；
- 返回 `queued`、`running`、`completed`、`failed` 四种异步任务状态；
- SQLite 保存任务请求、状态、结果或错误摘要。

### 系统集成接口（离线回放范围）

- 可将数据根目录内的 TDMS 注册为数据资产，保存 TDMS 元数据及文件大小/修改时间；接受方可显式要求 SHA-256 完整性清单；
- 已注册数据资产可作为分析任务输入，避免调用方传递任意操作系统路径；同一文件版本重复注册应幂等；
- 支持采集端状态上报契约（设备 ID、在线状态、通道数、采样率、最新 TDMS 相对路径），仅作为本地模拟采集端适配器；
- 持续性预警生成独立告警事件。配置受控 HTTP 接收端时，按 JSON/Webhook 投递，记录投递结果，并在 5xx/连接失败时最多重试 3 次；
- 不宣称实现厂商 DAS、SCADA、PLC 或现场硬件协议。生产接入需以设备厂商协议、鉴权和网络隔离要求为准。

### 风险初筛

- 计算 RMS、峰值、主频、局部 RMS 比、2–120 Hz 频谱偏离、相邻通道相干性；
- 用 median/MAD 和迭代背景池完成稳健背景学习；
- 需要幅值、局部差异和频谱偏离共同满足阈值后才形成候选；
- 合并连续候选通道为通道区间，输出 normal/yellow/orange/red 风险等级。

### 持续性和结果

- 支持同一文件的连续时间窗口持续性；
- 支持同目录连续 TDMS 文件的跨文件持续性；
- 记录候选次数、最长连续次数、差分 RMS、主频稳定性和相邻相干性；
- 浏览器显示单文件任务的 RMS 图与 JSON 结果，并可下载逐通道 CSV；
- Linux 日志记录启动、任务参数、完成耗时、候选/预警数及异常堆栈。

## 3. 验收标准

1. 在 Ubuntu/WSL 中启动服务后，Windows 浏览器可访问 `http://127.0.0.1:8000`；
2. 可从 `/mnt/f/数据` 读取真实 TDMS 的有限窗口，不复制或修改原始文件；
3. 可完成单窗口分析、多窗口持续性、跨文件持续性任务，并通过接口查询结果；
4. 正常合成数据不产生候选；相邻异常合成通道能形成区间；反复异常能升级，单次异常不升级；
5. `pytest` 覆盖数据安全、算法规则、接口边界和任务回归；Allure 可生成报告；
6. 日志可依据 `job_id` 追溯一次任务；
7. 不将任一初筛或预警结果表述为现场泄漏结论。
8. 数据接入、采集端状态、分析任务、告警事件投递各自具有可测接口契约；本地 HTTP 接收端可验证告警 JSON 与重试行为。
